# Создание модуля на основе шаблона

В библиотеке есть шаблон пустого модуля, из которого быстро создается новый модуль для **1С-Битрикс**.

## Установка

Подключаем как зависимость через composer из внешнего репозитория на GitHub. В `composer.json` добавьте следующие изменения:

```json
{
    "repositories": [
        {
            "type": "git",
            "url": "https://github.com/Dark-Servant/BitrixModuleHelper.git"
        }
    ],
    "require": {
        "dark_servant/bitrix_module_helpers": "dev-master"
    }
}
```

Затем выполните `composer install` или `composer i`

## Процесс создания нового модуля

1. **Копирование шаблона.** Скопируйте целиком папку шаблона `vendor/dark_servant/bitrix_module_helpers/Templates/empty.module` в папку `modules`.

2. **Присвоение кода модуля.** Переименуем скопированную папку в соответствии с предназначением модуля, обычно, имя нового модуля имеет вид `автор.название`, это же и код модуля. Этот код модуля служит идентификатором модуля в системе и базой для всех замен на следующем шаге.

3. **Замены в файлах модуля.** В новом модуле поправим 4-е файла. К примеру, для модуля `alanmilne.pooh` исправления выглядят так:

   - `include.php` — `EMPTY_MODULE_` → `ALANMILNE_POOH_` (определение констант);
   - `lang/ru/install/index.php` — `EMPTY_MODULE_` → `ALANMILNE_POOH_` (ключи языковых фраз);
   - `lib/EventHandles/Install.php` — `Empty\Module\` → `Alanmilne\Pooh\` (объявление пространства имен);
   - `install/index.php` — `empty_module` → `alanmilne_pooh` (имя класса установщика модуля).

4. **Языковые фразы.** Дадим название модуля (не идентификатор модуля). Это делается в файле `lang/ru/install/index.php`, в значениях, оканчивающихся:

   - на `_MODULE_NAME` (в шаблоне — `Модуль "Пустой модуль"`), это название нового модуля;
   - на `_PARTNER_NAME`, вместо пустой строки укажите название партнёра (автора) модуля.

   Для модуля `alanmilne.pooh` это выглядит так:

   - `$MESS['ALANMILNE_POOH_MODULE_NAME'] = 'Истории о Винни Пухе';`
   - `$MESS['ALANMILNE_POOH_PARTNER_NAME'] = 'Сказки Алана Александра Милна';`

5. **Версия модуля.** В файле `install/version.php` у ключа `VERSION_DATE` поставьте текущую дату в формате `ГГГГ-ММ-ДД`.

## Создание дочернего модуля

Дочерний модуль создается тем же процессом, что и обычный, но с дополнительным шагом - в файле `install/index.php` вместо подключения библиотечного класса через `use DarkServant\BitrixModuleHelpers\Main as ModuleMain;` указывается файл `install/index.php` родительского модуля, а родительским классом становится класс установщика родительского модуля:

Пример: создается модуль `alanmilne.honeytypes` как дочерний к модулю `alanmilne.pooh`.

```php
<?php
require_once __DIR__ . '/../../alanmilne.pooh/install/index.php';

class alanmilne_honeytypes extends alanmilne_pooh
{}
```

Теперь при установке дочернего модуля сначала устанавливается родительский (если еще не установлен), а при удалении родительского модуля сначала удаляются все его дочерние модули.

## Настройки модуля

- В шаблоне есть необязательный файл `options.php` — пример формы настроек модуля. Он построен на классах библиотеки
  * `DarkServant\BitrixModuleHelpers\Admin\Options\Form`
  * `DarkServant\BitrixModuleHelpers\Admin\Options\Tab`
  * и элементы ввода `DarkServant\BitrixModuleHelpers\Admin\Options\Input`
  
  позволяющих собрать страницу настроек, не разбираясь в html-верстве **Битрикс** для административной части.
- При удалении модуля сохраненные настройки никуда не исчезают, их значения сохраняются и восстанавливаются при повторной установке, что позволяет дорабатывать и спокойно переустанавливать решение. Чтобы полностью удалить информацию о модуле, включая сохраненные настройки, надо удалять модуль, перейдя на страницу со списком модулей в административном разделе с GET-параметром `DarkServantMdlClean` равным `Y`, либо при инициализированной PHP-константе `DARK_SERVANT_MDL_CLEAN` равной `true`.
