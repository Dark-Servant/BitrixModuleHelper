# Создание модуля на основе шаблона

В библиотеке есть шаблон пустого модуля — папка `Templates/empty.module`. Из неё создается новый модуль для **1С-Битрикс** по следующему процессу.

## Установка

Библиотека подключается как зависимость через composer из внешнего репозитория на GitHub. В `composer.json` проекта укажите репозиторий и требуемый пакет:

```json
{
    "repositories": [
        {
            "type": "git",
            "url": "https://github.com/Dark-Servant/BitrixModuleHelper.git"
        }
    ],
    "require": {
        "dark_servant/bitrix_module_helpers": "dev-master"
    }
}
```

Затем выполните `composer install`. Автозагрузка классов библиотеки подключается штатным `vendor/autoload.php` — в проекте на Битрикс это удобно сделать в `php_interface/init.php`:

```php
if (file_exists($_SERVER['DOCUMENT_ROOT'] . '/local/vendor/autoload.php')) {
    require_once $_SERVER['DOCUMENT_ROOT'] . '/local/vendor/autoload.php';
}
```

## Процесс создания

1. **Подготовка папки модулей.** В корне проекта (там, где лежит папка `vendor` с этой библиотекой) проверьте, существует ли папка `modules`. Если её нет — создайте.

2. **Копирование шаблона.** Скопируйте папку шаблона `vendor/dark_servant/bitrix_module_helpers/Templates/empty.module` целиком в папку `modules`.

3. **Присвоение кода модуля.** Переименуйте скопированную папку в код модуля — имя вида `автор.название` (в примерах: `nightmares.freddy` и `alanmilne.pooh`). Это имя служит идентификатором модуля в системе и базой для всех замен на следующем шаге.

4. **Замены в файлах модуля.** В скопированном модуле поправьте 4-ре файла, выполнив в них текстовые замены. Для модуля `alanmilne.pooh` они выглядят так:

   - `include.php` — `EMPTY_MODULE_` → `ALANMILNE_POOH_` (определение констант);
   - `lang/ru/install/index.php` — `EMPTY_MODULE_` → `ALANMILNE_POOH_` (ключи языковых фраз);
   - `lib/EventHandles/Install.php` — `Empty\Module\` → `Alanmilne\Pooh\` (объявление пространства имен);
   - `install/index.php` — `empty_module` → `alanmilne_pooh` (имя класса установщика модуля).

5. **Языковые фразы.** В файле `lang/ru/install/index.php`:

   - значение фразы с ключом, оканчивающимся на `_MODULE_NAME` (в шаблоне — `Модуль "Пустой модуль"`), замените на название нового модуля;
   - в элементе с ключом, оканчивающимся на `_PARTNER_NAME`, вместо пустой строки укажите название партнёра (автора) модуля.

   Для модуля `alanmilne.pooh` это выглядит так:

   - `$MESS['ALANMILNE_POOH_MODULE_NAME'] = 'Истории о Винни Пухе';`
   - `$MESS['ALANMILNE_POOH_PARTNER_NAME'] = 'Сказки Алана Александра Милна';`

6. **Версия модуля.** В файле `install/version.php` у ключа `VERSION_DATE` поставьте текущую дату в формате `ГГГГ-ММ-ДД`.

## Создание дочернего модуля

Дочерний модуль создается тем же процессом, что и обычный (шаги 1–6), с одним отличием в файле `install/index.php`. Пример: создается модуль `alanmilne.honeytypes` как дочерний к модулю `alanmilne.pooh`.

Вместо подключения библиотечного класса через `use DarkServant\BitrixModuleHelpers\Main as ModuleMain;` подключите файл `install/index.php` родительского модуля, а родительским классом укажите класс установщика родительского модуля:

```php
<?php
require __DIR__ . '/../../alanmilne.pooh/install/index.php';

class alanmilne_honeytypes extends alanmilne_pooh
{
    /**
     * Здесь надо просто объявлять константы с описанием данных,
     * которые будут установлены при установке модуля или удалены
     * при его удалении
     */
}
```

Установку и удаление родительского модуля библиотека берет на себя: при установке дочернего модуля сначала устанавливается родительский (если еще не установлен), а при удалении родительского модуля сначала удаляются все его дочерние модули.

## Настройки модуля

- В шаблоне есть необязательный файл `options.php` — пример формы настроек модуля. Он построен на классах библиотеки (`DarkServant\BitrixModuleHelpers\Admin\Options\`: `Form`, `Tab` и элементы ввода `Checkbox`, `Text`, `Textarea`, `Radio`, `Selectbox`), позволяющих собрать страницу настроек, не разбираясь в html-верстве **Битрикс** для административной части.
- При удалении модуля сохраненные настройки никуда не исчезают: библиотека сохраняет их и восстанавливает при повторной установке, что позволяет дорабатывать и спокойно переустанавливать решение.
- Чтобы полностью удалить информацию о модуле, включая сохраненные настройки, надо удалять модуль, перейдя на страницу со списком модулей в административном разделе с GET-параметром `DarkServantMdlClean` равным `Y`, либо при инициализированной PHP-константе `DARK_SERVANT_MDL_CLEAN` равной `true`.

## На что обратить внимание

- При правках файлов сохраняйте их исходную кодировку (UTF-8) и наличие/отсутствие BOM.
- Класс установщика в `install/index.php` наследуется от `DarkServant\BitrixModuleHelpers\Main`, поэтому библиотека должна быть доступна через composer.
- Названия, упомянутые в шагах 5, попадают в интерфейс административного раздела при установке модуля.

## Примеры

По этому процессу были созданы модули:

- `modules/nightmares.freddy` — «Кошмарики Фредди», партнёр «Разные ужасы»;
- `modules/alanmilne.pooh` — «Истории о Винни Пухе», партнёр «Сказки Алана Александра Милна»;
- `modules/alanmilne.honeytypes` — «Любимые виды мёда Винни Пуха», партнёр «Сказки Алана Александра Милна» (дочерний модуль к `alanmilne.pooh`).
